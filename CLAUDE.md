## Project Overview

`scalify-cli` is a Go CLI tool and MCP server for the **Scalify Platform** — generated by [cli-printing-press](https://github.com/mvanhorn/cli-printing-press) v4.2.2.

**Critical branding rule:** The CLI must never mention GoHighLevel, HighLevel, or LeadConnector anywhere in user-facing output, help text, docs, error messages, or flags. The underlying API provider is an internal implementation detail. All user-facing surfaces use "Scalify" exclusively.

## Commands

```shell
# Build both binaries
go build -o build/stage/bin/scalify-pp-cli ./cmd/scalify-pp-cli
go build -o build/stage/bin/scalify-pp-mcp ./cmd/scalify-pp-mcp

# Run all tests
go test ./...

# Lint
golangci-lint run ./...

# Verify structural quality
printing-press dogfood --dir . --spec ./spec.json
printing-press scorecard --dir . --spec ./spec.json

# Check CLI health (requires SCALIFY_TOKEN)
./build/stage/bin/scalify-pp-cli doctor
```

## Architecture

Generated Go CLI project following printing-press conventions:

- `cmd/scalify-pp-cli/` — CLI entry point (Cobra)
- `cmd/scalify-pp-mcp/` — MCP server entry point
- `internal/cli/` — one file per resource + compound commands (`sync`, `search`, `workflow`, etc.)
- `internal/client/` — HTTP client wrapping the Scalify API; `authHeaderPrefix = "Bearer "` constant is required for dogfood auth-protocol check
- `internal/config/` — TOML config + env-var auth (`SCALIFY_TOKEN`); `AuthScheme = "Bearer"` constant
- `internal/mcp/` — MCP server: `scalify_search` + `scalify_execute` cover every endpoint
  (`code_orch_scalify.go`, hand-owned), plus the CLI's utility tools mirrored from the Cobra tree
- `internal/store/` — SQLite cache with FTS5 full-text search

Config file: `~/.config/scalify-pp-cli/config.toml`  
SQLite DB: `~/.local/share/scalify-pp-cli/data.db`

## Auth

Set `SCALIFY_TOKEN=<api-token>` or run `scalify-pp-cli auth set-token`. The token is sent as `Authorization: Bearer <token>` on every request.

## Key Printing Press Conventions

- Auto-JSON output when piped (no `--json` flag needed)
- `--compact` returns only high-gravity fields (id, name, status, timestamps)
- `--agent` sets all agent-friendly defaults (`--json --compact --no-input --no-color --yes`)
- Typed exit codes: `0`=success, `2`=usage, `3`=not found, `4`=auth, `5`=API error, `7`=rate limited
- `--data-source auto|live|local` controls API vs cached reads

## Branding Invariant

The `internal/config/config.go` `BaseURL` points at the underlying API endpoint — this is intentional and must stay. It is never exposed in user-facing output. The `doctor` command intentionally omits the `base_url` field for this reason.

## Regenerating the CLI

Generated from the **live v3 API docs** (https://marketplace.gohighlevel.com/docs/llms/v3/llms.txt), not
a community spec. Everything lives in `scripts/regen/` (see its README):

```shell
# printing-press v4.2.2 (same version that wrote this repo)
GOTOOLCHAIN=go1.26.3 GOBIN=$HOME/bin go install github.com/mvanhorn/cli-printing-press/v4/cmd/printing-press@v4.2.2

PRINTING_PRESS=$HOME/bin/printing-press ./scripts/regen/regen.sh
go test ./... && git diff --stat
```

- `scripts/regen/endpoints.txt` is the list of endpoints the CLI wraps. Add a line, re-run.
- `scripts/regen/renames.tsv` gives clumsy generated command names a readable name.
- Hand fixes are re-applied on every run: `scripts/regen/patches/*.patch` (location switching, auth,
  doctor update check, `Version: v3` header), plus the hand-owned files `internal/cli/location_config.go`,
  `internal/cli/location_default.go`, `internal/client/query.go` and `internal/mcp/code_orch_scalify.go`. Change those files, then refresh the
  matching patch, or the next regen undoes your change.
- `spec.json` is the merged OpenAPI input the CLI was generated from; it's an output of the script.

## Releasing

**Always use `--parallelism 2` when running goreleaser.** The config builds 2 binaries × 6 platforms = 12 concurrent Go compiler processes by default, which exhausts RAM and freezes the machine.

```shell
# Correct — always use this
goreleaser release --clean --parallelism 2

# Or via Makefile
make release
```

Never run `goreleaser release --clean` without `--parallelism 2`.

## CLI/MCP Surface Parity — read this before touching path params or headers

`internal/cli/*.go` (the Cobra commands) and `internal/mcp/` (`code_orch.go` + `code_orch_meta.go`,
behind `scalify_search` / `scalify_execute`) each carry their own copy of every endpoint's path and
params. Both are generated from `spec.json`, so **fix endpoint shapes in the regen pipeline, not by hand**: an
edit to one generated file doesn't reach the other surface and is lost on the next regen.

- Endpoint data wrong (path, method, params): it comes from the live docs. Re-run
  `scripts/regen/regen.sh`; if the docs themselves are wrong, adjust `scripts/regen/merge.py`.
- Behaviour every command needs (headers, query handling): put it in a hand-owned file or a
  patch under `scripts/regen/`, and make sure it covers `scalifyExecute` in `code_orch_scalify.go` too.
  Example: `client.WithQuery` sends query params on POST/PUT/DELETE: `fix_write_query.py` wires it
  into the CLI, `scalifyExecute` uses it for the MCP.
- Then `GOTOOLCHAIN=go1.26.3 go build ./... && go vet ./... && go test ./...`.

If you only fix one surface, say so in the commit message under a "Known gap" note.
