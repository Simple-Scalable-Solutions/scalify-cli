# scalify-cli v2.0.0

Rebuilt from the current (v3) API docs. Commands that had stopped working against the live API work again,
103 new commands are added, and the MCP server now covers the whole API in about 375 tokens of tool
definitions instead of about 62,000. **Command names changed**: scripts that call the old names need updating
(table below).

## Upgrade

```bash
curl -fsSL https://raw.githubusercontent.com/Simple-Scalable-Solutions/scalify-cli/main/install.sh | bash
curl -fsSL https://raw.githubusercontent.com/Simple-Scalable-Solutions/scalify-cli/main/install-skill.sh | bash
```

Windows: `install.ps1` / `install-skill.ps1`. Then start a new Claude Code session. Your token and saved
locations (`~/.config/scalify-pp-cli/config.toml`) carry over unchanged.

MCP server users (Claude Desktop extension or `claude mcp add`): reinstall it to get the new tools.

## What's new

- **Every request uses API version v3**, generated from the live docs. 195 endpoints: 92 kept, 103 added,
  30 that no longer exist in the API removed (with replacements below).
- **New areas**: workflow definitions, logs, search and create/delete (where HighLevel has enabled the
  workflow API); social media statistics, posts and accounts; email templates and campaigns with stats;
  conversation search with filters, recordings and transcripts; custom objects and their fields; invoices,
  estimates, schedules and templates; orders, transactions, subscriptions and coupons; products, prices and
  inventory; funnel pages and redirects; blogs, courses, proposals, notes search, task search.
- **MCP server: search + execute.** Two tools cover every endpoint: `scalify_search` finds the endpoint for a
  task and lists its params, `scalify_execute` calls it. `locationId` fills in from the active location.
- **Location fills in by itself** on any command with a `--location-id` flag.
- **`sync` covers 31 resources** for the active location (contacts, conversations, opportunities, workflows,
  invoices and more), for `search`, `analytics`, `tail` and `--data-source local`. `search` now respects
  `--agent`, `--compact` and `--select`.

## Fixed

- Contact search, conversation filters and most list commands failed against the current API.
- Query params (e.g. `locationId`) were dropped on POST/PUT/DELETE: social statistics, workflow search and
  10 more failed with 401 "Location ID is required".
- `locationId` was added to every request, and the API now rejects it where it isn't expected (422).
- Commands whose docs declare params unusually sent a literal `{id}` in the URL, read the wrong argument,
  or never sent their body: conversations get-message/get-email, locations timezones/templates, emails
  get-campaign-stats, contacts update-tags/tags remove, invoices delete-estimate, payments orders and others.
- List commands never sent `offset=0`, which invoices, estimates and funnel redirects require.
- `sync` pulled nothing with a location token; `search` with no `--type` skipped most resources.

## Known gaps

- **Workflow API** (definition, logs, status, search, create, delete) only works on sub-accounts HighLevel has
  enabled; elsewhere it returns 403 `WORKFLOW_API_NOT_ENABLED_FOR_LOCATION`. `workflows list` works everywhere.
- **Not tested live**: invoice void, funnel redirects, workflow writes, and the few routes that need an agency
  token (location search, users filter-by-email, location update).
- `--select` on nested list output (#9) and per-command location (#10) are still open.
- API quirks: estimates need `title` and `expiryDate` (docs say optional); notes search `relations` takes
  `[{"objectKey":"contact","recordId":"<id>"}]`.

## Tested

- Every read command run against a real sub-account: 98 of 122 return data, 6 reach the API with nothing to
  return; the rest need an agency token, data that sub-account doesn't have, or the workflow API.
- Create/read/update/delete of everything writable on a playground sub-account (`scripts/e2e/crud.py`):
  93 steps ok, 0 broken, nothing left behind.
- `go test`, dogfood and scorecard (89/100) pass.

## For maintainers

- Regenerate from the live docs: `scripts/regen/regen.sh` (see `scripts/regen/README.md`). Hand fixes are
  re-applied on every run.
- Before a release: `python3 scripts/e2e/crud.py --dry-run --contact-email <you>`, then the live run.
