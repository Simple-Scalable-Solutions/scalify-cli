# scalify-cli v2.1.0

Run a command against another account without switching, clearer errors when a token can't reach an
account, field picking that works on every list, and brand boards. No command names changed.

## Upgrade

```bash
curl -fsSL https://raw.githubusercontent.com/Simple-Scalable-Solutions/scalify-cli/main/install.sh | bash
curl -fsSL https://raw.githubusercontent.com/Simple-Scalable-Solutions/scalify-cli/main/install-skill.sh | bash
```

Windows: `install.ps1` / `install-skill.ps1`. Then start a new Claude Code session. Your token and saved
locations carry over unchanged. Check with `scalify-cli version` (should say 2.1.0).

## What's new

- **`--location <id-or-name>`** on every command: runs that one command with that saved account's token.
  The active location doesn't change, so nothing is left pointing at the wrong client.
  `scalify-cli contacts search --page-limit 10 --location "Scalify Demo"`
- **Commands given an account id use that account's token**: `locations custom-values list <id>` works for
  any saved account, not only the active one (it used to fail with 403). The MCP's `scalify_execute` does
  the same for `locationId`.
- **Brand boards**: `brand-boards` commands for design kits (brand colours, fonts, logos) and brand voices:
  list, get, create, update, delete, set default.
- **More fields from the latest docs**: tags take `color`, `description` and `categoryId`;
  `opportunities search` takes `filters` and `sort`, with fewer required fields.

## Fixed

- **`--select` on lists** (#9): `workflows list --select id,name` returns each workflow's id and name (it
  returned nothing). A `--select` that matches nothing now warns and lists the fields you can pick.
- **`--compact`, `--csv` and the table view on lists**: they now find the list inside the response, so
  `--compact` actually shrinks output and `--csv` gives CSV even when piped.
- **403 / 401 errors** (#4): say which account's token was used, and how to use or add another one.

## Known gaps

- Brand-board **custom colours** (the `{{ brandboards.… }}` tags in emails) aren't in the public API: the
  endpoint refuses location tokens. Set them in the CRM.
- Brand-board create/update/delete commands are read-checked only; the write test suite doesn't cover them yet.

## Tested

- Unit tests, `go vet`; a full regen reproduces the tree.
- Live, read-only, on Scalify Demo: `--location` by id and by name, account-id token pick (CLI and MCP),
  403 hint, `--select` / `--compact` / `--csv` on lists, design kits, brand voices, opportunity search.
- Write suite (`scripts/e2e/crud.py`) in dry-run mode: 89 write routes build the right requests.
